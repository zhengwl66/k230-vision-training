# 7. 颜色识别、补拍与排查

## 颜色为什么不跟YOLO一起训练

七类YOLO识别形状；颜色使用独立的白托盘参考校正、彩色前景连通区域、亮度归一化、Lab/CIEDE2000原型匹配。深蓝与浅蓝都输出BLUE/蓝色，紫色为PURPLE/紫色。推理不根据形状或所在位置猜颜色。

本次仓库带的是已验证20261014颜色模块，算法和原型没有改动。来源及测试向量见THIRD_PARTY_NOTICES.md。三种姿态也不是靠颜色判断。

颜色出错时先检查曝光、白平衡、白盘是否有中性参考、反光和物块是否完整落在框内。深蓝→紫色或四角未知时，采集同一物块中间/四角及换位图，逐件明确真色，单独标记颜色校准集与留出集。修改原型需复核红/黄/绿等旧色，不能仅扩大蓝色范围把紫色覆盖掉。

仓库包含当前颜色推理代码和34组CIEDE2000标准公式测试，但不把仅补训形状模型说成已重新校准颜色。未知是拒识结果；color_support是相对支持度，不是概率。

## 提高精度的优先顺序

1. 保存真实误判原图，明确是错形状、漏检、重复框、错状态还是错颜色。
2. 补拍实际难例周围的多位置/角度，不只重复同一姿势几十帧。
3. 标注复核，保留旧七类数据；按批次隔离验证与测试。
4. 对比旧版在同一验证集和独立测试集上的逐类TP/FP/FN及状态未知率。
5. 在目标K230、实际分拣相机档位和规划阈值下复核。

## 常见问题

| 现象 | 先检查 |
|---|---|
| 一件物块偶尔出现两个框 | 空盘误检、相邻阴影、跨类重叠；不是简单把数量强制限制为1 |
| 原角度正常，换角度漏检 | 新角度覆盖不足、投影改变、遮挡；补数据再训练 |
| 姿态持续未知 | 模型文件配套性、crop大小、可见前景、连续帧确认及新姿态覆盖 |
| 复制了新模型仍用旧版 | KMODEL_PATH、MODEL_PATH、实际导入文件、脚本是否重启、版本与SHA |
| 预览报uvc_camera不存在 | 补回相机模块，或修改CAMERA_MODULE_DIR/MODULE指向原采集模块 |
| COM口占用 | 停止脚本，断开其他CanMV/串口客户端，避免两处同时连接 |
| USB摄像头枚举/JPEG解码异常 | 停止脚本，检查供电与USB Host连接，必要时完全断电后重新上电 |

程序效率优化需要分别计时取帧、预处理、KPU、颜色、姿态和预览输出。本仓库整理没有降低输入尺寸、跳过颜色或减少姿态步骤，不能把流程整理宣称为已提速。
